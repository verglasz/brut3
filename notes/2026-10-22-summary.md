# Session summary, 2026-10-21/22

## Goal that emerged

The deliverable is a **Haskell** agent (base only, Safe Haskell, no SIMD, source size not
capped) for a contest at **5 minutes per game**, roughly 12 s per move. The Rust project is
the lab and the trainer. Open questions about the contest: memory limit, exact time control
(per player / increment / first-move allowance), core count.

## Measurements that decided things

| match (40 games) | score for the first |
|---|---|
| greedy vs minimax 4 | 0.04 |
| greedy vs mcts 200 | 0.06 |
| minimax 4 vs mcts 200 | 0.81 |
| minimax 6 vs mcts 100k | 0.06 |
| minimax 6 vs mcts 400 | 0.84 |
| minimax 6 vs mcts-nn 400 (board-v2 128/4/4, gen 12) | 0.65 |
| mcts 100k vs mcts-nn 400 (gen 12) | 0.975 |

- Random-playout MCTS costs about **1.3 µs per simulation** in Rust (100k sims ≈ 130 ms
  per move, one thread). It is the strongest agent in the project.
- The generation-12 transformer makes each simulation worth 3 to 5 playouts; an evaluation
  costs 100+ playouts. Per CPU second the rollouts win by more than 10x, so **the
  transformer is not worth running in Haskell**.
- The 128/4/4 widening was not free: generation 1 ran at 31k sims/s vs ~110k for 64/2/4.
- Twelve generations (~25k games, ~1M positions) is a fraction of a percent of the data the
  published runs needed (Jones: ~1e9 samples for 9x9 Hex); slow learning is expected scale,
  not a parameter bug.

## Literature anchors (Jones 2021, "Scaling Scaling Laws with Board Games")

- ~500 Elo per 10x train compute on the frontier (~150 Elo per doubling).
- 10x train compute replaces ~15x test-time search.
- 9x9 Hex to perfect play in under 3 h on one RTX 2080 Ti with a 2x512 MLP (~500k params,
  ~500 KFLOPs per position) and 64-node searches. UTTT is the easier game.
- AlphaZero: 800 sims per move, 20x256 resnet (~25M params, GFLOPs per position).

## Decisions

1. **Contest engine = Haskell rollout MCTS** first: bitboards, compact arena (no stored
   state per node), tree reuse across moves (and pondering), the solver, time management,
   win-now/block-now playouts, an opening book searched offline.
2. **Network only if it clears a bar**: `mcts-nn <net> 10000` beats `mcts 100000` in the
   Rust benchmark (≈ the Haskell cost ratio). Design for it ("NNUE-shaped"):
   - inputs: 9 board content ids (mover's perspective, 3^9 each) + forced board (10);
   - shared content table E 19683x64, mix Linear(9x64 -> 256) (+ forced table 10x256), ReLU;
   - 256 -> 32 -> 32, ReLU; value 32 -> 3 (+ linear value readout from the accumulator);
     policy 32 -> 81 + local policy table P 19683x9 added per board;
   - extra feature rows: big-board line patterns (8 lines x 64 states), the forced board's
     own content table, game phase;
   - export with T[k][c] = W_k E[c] folded (9x19683x256, ~180 MB f32) so a Haskell eval is
     ~12k multiply-adds (~30-50 µs): 9 row adds + 256x32 + 32x32 + legal-move logits;
   - train by distillation from the rollout search, then continue in the loop with `--init`.
3. Pure MCTS stays single-threaded; parallelism is `selfplay --threads`.
4. W/D/L through the search was tried and reverted (bigger nodes, little value); the scalar
   root value is recorded instead.
