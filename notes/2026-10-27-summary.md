## Tools

- **`serve ADDR SPEC..`**: a page (utttai's look) to play against any agent spec, hints from a
  third. Std-only HTTP, one thread per connection, one agent thread owning every agent (they
  need not be `Send`); stateless API, the game is the move list.
- **`prune-book`**: ships a smaller book. Entries are *marked* `dropped`, never deleted, because
  every later walk (deepening, common lines) needs them; prune passes can then run in place, at
  different depths with different settings. Options: `--agent SPEC` drops entries whose move
  the agent plays anyway (`--min-advantage a`: the book move's class, up to the position's
  symmetries, must lead the agent's second choice by `a`); `--keep-replies k` keeps the lines
  whose replies each had at least `k` of the visits, judged reply by reply; `--drop-rare r`
  drops entries on the book's lines but off the `r` lines (only those: an entry the walk does
  not reach is not known to be rare); `--from-ply`. Each pass adds a header line.
- **`book --main-lines`**: deepens only along the parent's book move. Dropped entries count as
  missing for the frontier; one inside the new tree comes back from its stored search if that
  had at least the current budget (n sims store n - 1 visits), else it is searched again. So:
  deepen first, prune last. Fixed while checking: a missing position first reached off a book
  move was marked seen, so a later main-line path to it was skipped.
- **`export`**: `--out -` prints every file (`-- file: Gen/X.hs` with a blank line around);
  messages always go to stderr. No `--model` needed for FixedVec alone: its flags go after
  `--` (or as one string in `--vec-extra`), documented in `export --help`. The report and
  Net.hs's header give the flags that rebuild the same FixedVec without a model. `vecgen.py`
  is legacy: nothing refers to it any more, and the Rust generator is the reference.

## The book's key, in steps

1. 81 absolute cell digits + forced board (the start).
2. Decided boards as one status digit repeated (`3` won by X, `4` won by O, `5` full), plus
   a side-to-move digit, since marks no longer give it. Positions differing only inside
   decided boards share an entry: they play the same.
3. Relative to the side to move (`1`/`2` mine/theirs, `3`/`4` won by me/them, `5` full), no
   side-to-move digit: colour-swapped twins share an entry too. 82 digits again.
4. The file stores the key (`format 2` line before the entries, so old files are never
   misread); `state_of_key` rebuilds a position: a won board as the winner's top row, a full one
   as `XOX OXX OXO`, X to move, and a last move only for its square (BitState reads nothing
   else of it). Ply comes from the book walk's depth (`Book::plies`), not from marks.

Old files (absolute cells, or the interim 83-digit keys) still load. Lines that share a key
**pool** their searches (visits add up, visit-weighted value, most visited move, live if
either was): the positions have the same moves. `models/book.txt` pools 4 lines (all colour
twins). Checked end to end: every live line of three old books, from all 8 images, gives the
same move (or a symmetry-equivalent one) through the converted book; 0 different, 0 missing.

## Exporter, round 2 (the 26th) and the book format

- Per-content tables split into named fields (`OpenClosed`), shipped as `_open` and `_rest`
  arrays (the decided kinds, no-forced, cells, pad, taken apart by pattern), so the decoder
  never `splitAt`s a long list.
- Bundle markers, prefixed internals, Safe everywhere; one-line Haddock on every exported
  item; Weights.hs and BookContent.hs open with a DATA BLOB WARNING and a rough size.
- Book.hs split into Book (decoder, keys) and BookContent (the data). Entries: nine
  little-endian `Word16` board codes (open: base-3 digits, square 0 most significant, from the
  mover's view; 19683/19684/19685 decided), the forced board, the move: 20 bytes, down from
  25. `BookKey` = five `Word32`, two fields per word (`hi .<<. 16 .|. lo`), derived `Ord` =
  key order; built by `bookKeyOfBoards :: [Word16] -> Word8 -> BookKey`, `INLINE` (checked in
  Core: a call on a literal list builds the key with no list), decoded by `bookEntries` with
  `decodeU16lePiecesWith` and an explicit 10-element match. `type Symmetry = [Int]`.
- Measured on GHC 9.10.3: a key of 3×Word64, 5×Word32 or 9×Word16+Word8 all take 32 bytes
  (small strict fields are packed); a tree node with key and move takes 48 either way.

## Generated code layout

- Indices padded per role (`a00 .. a63`, `v00_00`, `acc00 .. acc64`).
- Patterns and constructions are expression trees laid out recursively: one line, unless a
  child is over 30 characters (or over 16 on a line over 300), then one child per line;
  short children on a line of 250+ go into a rectangle (rows of k under the first child, k a
  divisor of their count, powers of two first, widest under 100 columns; ragged if none).
- Sums split along their tree (a node fits in 100 columns or puts its two operands on their
  own lines, `+` leading); a sum stays on its definition's line when it all fits.
- Matches open all arguments in one `case (u, v, ..) of ( P, Q ) ->` (same Core as nested
  cases, checked); data declarations use the same layout.

## Lessons

- An interrupted command can still have done part of its work: a rejected `git stash && ...`
  left the changes stashed; check `git status`/`git stash list` after any interruption.
- zsh's MULTIOS sends `cmd 2>&1 >/dev/null | grep` stdout down the pipe too; capture stderr
  to a file instead.
- `-ddump-simpl` shows strict arguments still nested; whether they become thunks shows only in
  the final STG (`-ddump-stg-final`, updatable closures `\u []`).
